# Remvu：换一个 AI，项目接着做

Claude Code 额度用完，换到 Codex 时，代码还在，但用户的偏好、试过的路线和没完成的事可能丢了。Remvu 用一份 Markdown 交接文件留下这些背景。

日常只有两个动作：`save` 保存，`resume` 接着做。Claude Code 使用 `/remvu save`、`/remvu resume`，Codex 使用 `$remvu save`、`$remvu resume`。默认 skill 由当前 agent 直接读写文件，不需要 Python、hooks 或 Remvu 账号，不会在结束会话时拦住工作。

私有笔记保存在 `.remvu/notes/REMVU.md`。换电脑时，把代码和选定的交接文件一起带走；接手方不必安装 Remvu，直接读文件也可以。接手前仍需检查代码变化，旧的测试通过记录不能当作当前验证。

笔记区分用户确认、工具观察、agent 推断和待核实内容。被否决的方案保留原因，旧决定保留替代关系，失败检查和未知事项继续可见。它保存可解释的决策摘要，不导出隐藏思考链或无关聊天。

轻量版有明确边界：不会自动抓取所有工具调用，也没有强制的并发锁或内容指纹。需要这些能力时，可以使用现有的可选 Python 引擎；它保留严格格式、证据索引、并发检查和恢复工具。旧格式与历史版本继续可用。

多模型平台与 API 中转站也可以让用户在切换模型、客户端时，把项目背景一起带走。平台接入需要取得项目文件和可观察结果，单纯转发 API 请求无法补全操作记录。目前没有内置的中转站专用适配器。

公开分享需要单独请求和审阅，私人笔记不会自动上传或提交。诊断也由用户预览后决定是否提供。

当前仍是 v0.3.0-beta.1 候选版。普通 HANDOFF.md 是本轮真实对照的基线；如果两者效果相同，或 Remvu 更大、更慢，报告也会保留。现有结果不支持 token 或费用节省比例，Windows、桌面和 VS Code 原生验收继续单独列明。
