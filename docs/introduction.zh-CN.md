# Remvu：让下一个 AI 接着做

换一个 coding agent，项目最容易丢掉的是代码之外的信息：用户为什么坚持某个接口，哪条路线已经试过，某个“通过”是否真的运行了测试。

Remvu 把这些信息写进一个可随代码交接的 `REMVU.md`。接收方先读简短摘要，再查看决策、依据和未完成事项，不需要安装 Remvu 或翻原聊天。

它把用户确认、工具观察、agent 推断和待核实内容分开记录。旧决定被替代后仍保留历史；代码发生变化时，接收方能发现记忆对应的是旧状态。并发更新会检查版本，不会静默覆盖另一位 agent 的内容。

对多模型平台和 API 中转站的用户，Remvu 提供了一个直接的使用场景：换模型、换客户端时，把项目背景一起带走。目标、约束、已经否定的方案和下一步保存在项目里，减少每次重新交代背景的工作。平台运营者也可以把开放格式接入自己的 agent 客户端或工作流，提供项目记忆与跨模型接手能力。

这项能力需要客户端或工作流访问项目文件与工具结果，单纯的 API 请求转发无法自动完成。目前提供的是 Claude Code 与 Codex 适配，中转平台集成仍需另行接入；现有实测也没有给出 token 或费用节省比例。

本地完整记忆和事件放在忽略的 `.remvu/`。Claude Code 和 Codex 适配器通过生命周期 hooks 记录可观察事件，再由当前 agent 利用已有上下文整理。脚本不额外调用模型 API；记录和阅读本身仍占用上下文。

公开分享需要主动调用 `/remvu share` 或 `$remvu share`。输出只有一个可读文件，公开证据随内容一起带走，私人原始记录留在本地。文件生成后不会自动上传。

已发布的 v0.2.0 提供参考实现与开放格式提案。主分支正在准备 v0.3.0-beta.1，补齐稳定安装、升级回滚、健康检查和损坏恢复，让陌生用户也有可执行的安装与排错路径。新版仍需完成 macOS、Windows 及终端、桌面、VS Code 的真实验收，结果在[候选验证报告](beta-validation.md)逐项列明。

诊断文件只在本地生成，预览后才由用户决定是否提交。平台嵌入和开源自托管会在个人版测试后推进。没有可比较的完整任务实测时，项目不会给出 token 节省比例。
